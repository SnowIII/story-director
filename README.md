# 故事导演 · Story Director

> 一个挂在**任意 MVU 角色卡**上的剧情推进插件：把「接下来该演什么」交给 **故事神谕（Story Oracle）** 去设计，
> 插件自己负责调度、推进与落拍。**不用你手点，剧情会自己往前走。**

- **三条线**：主线（按章推进的长线）、支线（并行的短小线）、插曲（幕间小段）
- **全自动导演**：拍真的落进正文 → 自动换拍；章目标达成 → 自动请神谕开下一章；每 N 轮自动补支线 / 插曲
- **自带剧本规则**：规则文本在插件自带的世界书「故事导演」里（缺失时自动安装并挂到全局），你可以随时自己改
- **不碰角色卡自己的变量**：全部状态写在 `stat_data.故事导演` 命名空间下（与 MVU zod 严格结构也兼容）
- 借故事神谕的**模型连接**生成，不需要在酒馆里额外接一个 API；面板按钮与自动生成都走 `StoryOracleAPI.run()`

## 三、它是怎么转起来的

**剧情的引擎是「世界里发生了什么」，不是「你该去做什么」。** 这是这套东西最要紧的一条设计：

- 每一拍写成「**谁做了什么 → 于是局面变成什么样**」，主语永远是 NPC / 第三方 / 环境 / 一场意外
- 它**不安排 {{user}} 的行为**：不替你说话、不替你做决定、不写你的心理，也不写「等你…之后再…」
- 想让你参与，它会把**局面摆到你面前**（有人来传话、有东西被送来、有人当着你面做了什么），然后**停手**
- 推不动就用**伏笔与事件**推：一个被收起来的物件、一句没说完的话、一个别人做的决定、一次意外
- **你什么都不做，故事照样往前走** —— 世界不会等你

> 这条在注入里是**硬约束**（每轮都下发），在世界书里有一整节《推动剧情的引擎》。
> 「设定」页有个开关可以关掉它，但那是给「我就想看 AI 也演我」的玩法准备的，一般别关。

```
你正常 RP  ──►  正文模型每轮收到一份幕后引导：本章第 N 拍 + 支线 + 插曲
                     │
                     ├─ 拍真的写进正文 ──► 写 MVU 命令 _.set('故事导演.主线.本拍已落', true)
                     │                        │
                     │                        └─► 插件（1.5s 后）自动换到第 N+1 拍，下一轮注入新拍
                     │
                     └─ 整章目标达成 ──► 写 章目标达成 / 可进下一章
                                              │
                                              └─► 插件请**故事神谕**设计下一章（跨刷新不丢）
```

支线与插曲走同一条路：神谕给「切入 + 落点」，正文演到位就写回报，插件把它摘掉并（按节奏）再补一条新的。

### 三条线的分工

| 线 | 谁定内容 | 长度 | 什么时候动 |
|---|---|---|---|
| **主线** | 故事神谕（按自带世界书的规则） | 一章 3~6 拍，可以跨很多章 | 每轮聚焦一拍 |
| **支线** | 故事神谕 | 一条一个落点 | 默认每 8 轮补一条（最多同时 2 条在演） |
| **插曲** | 故事神谕 | 一到两个画面 | 默认每 6 轮补一条，接在某一拍之后才出现 |

主线 > 支线 > 插曲：注入块里写明了冲突时永远先照顾主线当前那一拍。

## 四、总纲（史诗）：主线为什么不平淡

只按章续写时，模型只能就着眼前写，很容易写成「跟着商队走来走去」这种流水账。
所以插件在开第一章**之前**，先请故事神谕定一部 **总纲** —— 一条**围绕 {{user}}** 的长线，跨越很多章：

```
总纲《商路上的三封密信》
├─ 总纲：他从一个只想安稳过日子的边镇小吏，被卷进使团倾轧与旧案清算……
├─ 走向：1. 一桩寻常差事把他推到使团门口   2. 他身边最亲近的人先被卷进去
│        3. 旧案浮出水面……               4. 一个不可逆的两难   5. 他身边的人付出代价
├─ 伏笔：使团随行名录上被划掉的名字；她腕上那道旧疤；城南空了很久的院子
├─ 既成事实：他被调任边镇；使团已在城外扎营
└─ 当前进程：试炼
```

**之后每一章都只是它的一拍**：一章只推进一小段，伏笔合适的时候兑现一个。

### 两条必须同时守住的原则

| 原则 | 意思 |
|---|---|
| **主角是 {{user}}** | 总纲写的是「围绕他**会**发生什么、他被卷进什么里面、他身边的人怎么变」。与他无关的势力动向只作背景。 |
| **但不替他行动** | 总纲写的是**世界会怎么压过来**（谁会找上他、什么会落到他头上），不是「他会怎么做」。写「他在两难里」可以，写「他选了哪边」不可以。 |

### 他不按剧本走怎么办

这是常态，不是异常。两道机制兜着：

1. **每开新章之前自动「重新校准」总纲**：插件会带着最近对话，让他实际做过的事进入「既成事实」；
   原来那段走向不成立了，就**换一条通往同一目标的路**；他走出了完全没想到的方向，就**顺着他的方向重新想这个故事的终局**。
2. **每一章的生成提示词里都有「演化守则」**：不以他的行为为前置条件、不写「让他回到原计划」的一章、
   也不写成「全世界立刻顺着他的选择变」（世界有自己的惯性与别人的目的，反应要有迟滞、有杂音）。

> 关掉「自动定总纲」与「每开新章前重新校准」（「设定」页），主线就退回逐章续写 —— 更省调用，也更容易平淡。

### 什么算主线的料，什么算间章的料

| | 主线 | 间章 |
|---|---|---|
| 跟着商队走、赶路、逛街、吃饭 | ❌ 不要 | ✅ 正是这里的内容 |
| 路上被劫 / 被查出 / 被认出来 | ✅（事件本身够格） | — |
| 局势变了、秘密揭开、关系重排、有人付出代价 | ✅ 至少一件 | ❌ 不推进 |
| 一个具体可复述的细节（伏笔） | ✅ 埋下并准备兑现 | ✅ 顺手埋，不当场兑现 |

**允许多线交织**：一条主线去铺垫另一条主线（旧案牵出旧人、小差事引出大清算）是受欢迎的，
多条这样的线交织成一部史诗完全可以接受 —— 但每条都要有自己的代价与后果，不能只是「下一步去哪」。

### 基调：只有两种，由你选（不由模型判断）

> 一开始我做了 10 档，太杂 —— 既难选，每档又写得太细。现在只留**两种真正不同类型的**故事，外加一个「自动」。

| 基调 | 是什么 | 一章的典型形状 |
|---|---|---|
| **自动** | 按角色卡与当前剧情自己判断（默认） | — |
| **奇幻 / 异世界 · 冒险史诗** | 世界比他的日常大得多：国与国、势力与势力、古老的东西醒过来 | 出发 → 遭遇人与异象 → 阴谋一角 → 陷进险境、付出代价 → 突围／反转 → 得到什么，同时失去什么 |
| **都市 / 日常 · 生活中的暗流** | 没有拯救世界，但**一样要有真正在推进的矛盾**：钱、工作、房子、家里的事、旧账、面子 | 寻常日子 → 不对劲的细节 → 有人瞒着或扛着 → 小事被摊开 → 关系或处境挪一格 |

**「日常」不等于「没有冲突」** —— 它只是把规模放小、放到人身上。基调里明确反对把日常写成没有张力的流水账
（吃饭、买菜、上班各写一遍，却没有一件事在往哪儿去），也明确**允许并欢迎轻喜剧调味**（误会、错位、逞强、
被当场拆穿 —— 但笑点来自局势，不靠谁变蠢）。

选完之后点一次「**重新定纲（换一部）**」才会按新基调重写总纲。
基调**只在给故事神谕的提示词里**，不进正文注入 —— 正文仍然只知道「这一章演什么」。

### 总纲要写清「贯通的矛盾」

「每章都发生了点事」不等于有矛盾。总纲必须回答：**这条线从头到尾在争什么？**（谁要什么、谁挡着、为什么现在非解决不可。）
没有那个矛盾，走向就只是一串事件，读者感觉不到「在往哪儿去」。
### 总纲是一条「有归宿」的完整弧线，不是一串越来越大的事件

只写大事件会变成大纲流水账，最后收不了场，也写不出回报与余味。所以总纲里的**走向**按弧线来写：

```
走向:
1. 起：什么把他卷进来
2. 承：事情露出真面目，他不得不下场
3. 转：撞上代价 / 反转 / 最坏的一下
4. 合：收场 —— 这件事最后是什么结果（不是「更大的事要来了」）
```

- **最后一条必须是归宿**：事情解决了 / 没能解决但代价付出去了 / 他变成了不一样的人。
- **大事件 ≠ 长线**：大事件是「发生了什么」，长线是「这一路他要付什么代价、变成什么样」。
- **允许总纲走完**：讲完就该收，到时候插件会请你（神谕）定下一条新的长线 —— 有始有终才是完整的故事。

## 五、两种幕：主线 与 间章

同一时间只有**一种幕**在演，两者互斥：

| 幕 | 是什么 | 什么时候 |
|---|---|---|
| **主线** | 一章若干「拍」，按拍推进，章目标达成才算走完 | 平时 |
| **间章** | 一段**日常**：生活质感、人物侧面、顺手埋伏笔 | 主线一章收尾之后 |

**为什么要有间章？** 主线一章演完到下一章准备好，中间本来是一段空档；空着就发闷，于是把这段时间交给间章 ——
主线不会「一时半会没内容」，读者也不会觉得戏断了。

**间章与主线最大的差别：它不要求跑完。**
`间章.拍` 里的几个「日常画面」只是**素材与顺序建议**：可以只挑一两个、可以跳过；
正文模型写到合适的地方就写 `间章.可回主线 = true` 收掉它（**不必等拍演完**），插件随即接着开主线的新一章。
你也可以在面板上直接点「**现在回主线**」或「**开一段间章**」手动接管。

> 写给间章的提示词里反复强调：**不要为了「把拍演完」而硬凑日常** —— 拖长的日常比跳过更难看。

## 六、节奏：它到底多久生成一次

这是最要紧的一项 —— 一个好的导演不该让玩家应接不暇。**所有节奏都按「轮」记账（1 轮 = 1 条 AI 回复），完全不看墙钟**：
你挂机三天回来不会一口气冒出十条新线，回来只补一条。

### 谁在决定节奏

| 线 | 什么时候会生成 | 默认多久一次 |
|---|---|---|
| **主线（开章）** | 拍列表为空 + 这个聊天已聊满 3 轮 | 只在开局或你清空后 |
| **主线（换章）** | 拍**全部演完** + 章目标达成 + 正文模型确认场景收尾 + 收尾后过够 `chapterGap` 轮 | 约每 25 轮（人类节奏实测算，中间夹着间章） |
| **间章** | 主线收尾 + 余波 `chapterGap` 轮（默认开）；或你点按钮 | 主线与主线之间的间隙 |
| **支线** | 在演条数 < 上限 + 距上次满 `threadEvery` 轮 | 约每 25 轮，最多同时 2 条在演 |
| **插曲** | 待演条数 < 上限 + 距上次满 `interludeEvery` 轮 | 约每 25 轮，最多同时 1 条待演 |

> ⚠ **换章不是计时器驱动的**：拍演完只代表演出计划走完了，还要正文模型写下 `章目标达成` 与
> `可进下一章`（它在正文里确认真发生了、且这个场景适合收尾）才换。所以「聊了几轮」并不直接决定换章，
> 而是**剧情真的走到那儿**才换 —— 这是防止剧情被强行推进的主要机制。

### 三道「别一直生成」的闸门

不管上面哪个计时器到了，都要再过这三关（「设定」页可调）：

| 开关 | 默认 | 作用 |
|---|---|---|
| **任意两次生成的最小间隔**（`autoCooldown`） | 3 轮 | **跨线生效**。没有它，支线和插曲会在同一个心跳里各发一次，一轮多烧两次调用、页面上同时冒出两条新线。有它之后一轮最多只生成一样东西。 |
| **上一章收尾后隔几轮才开下一章**（`chapterGap`） | 4 轮 | 留出「余波」的时间：让后果、别人的察觉、关系的位移先写出来，再开新章。**间章也是等这几轮之后才开**。 |
| **新章开头几轮先不插支线／插曲**（`threadWarmup`） | 3 轮 | 一章刚开，先让主线立住，别马上往里塞配菜。 |
| **主线收尾后自动开间章**（`autoInterludeChapter`） | 开 | 关掉之后，主线收尾就直接开下一章（没有日常的间隙，场子会空一点）。 |

### 实测密度

用「人类节奏」（平均约 3 轮演完一拍、6 拍一章，间章里约 2 轮收）跑 60 轮：

```
第 2 轮  定总纲（只一次）
第 5 轮  开第一章
第15轮  支线      第18轮  插曲
第24轮  间章      第29轮  换章
第39轮  支线      第42轮  插曲      第48轮  间章      第53轮  换章
→ 共 10 次生成 / 60 轮｜换章间隔 24、24 轮｜没有任何一轮冒两样
```

也就是说：**大约每 24 轮一章主线，中间用一段间章、一条支线与一条小插曲把空档填上**，
一分钟能读完的东西不会一次性堆给你。

**觉得还是太快**：把 `autoCooldown` 调到 6~10、`threadEvery` / `interludeEvery` 调到 20+，
或者直接把「自动导演总闸」关掉 —— 那样插件不再自己调模型，注入与手动按钮照常工作。
**觉得太慢**：把这三个调小；但注意每次自动生成都是一次真实的模型调用。

「当前」页的导演状态卡片里有一行**实时节奏提示**，随时告诉你「下一次什么能生成、还要等几轮」，
不用猜。

## 七、面板

左下角圆形的**场记板**图标（可拖动，位置记住）→ 打开面板：

- **当前**：正在演的章 / 拍列表（`✔` 已演、`▶` 本轮、`·` 未到）、支线、插曲、导演状态；
  间章时段这一块会整块换成间章内容（主线变灰收着）
- **总纲**：查看 / 手改这条长线（总纲、走向、伏笔、既成事实、进程）；「按现在的情况重新校准」「重新定纲（换一部）」
- **主线**：直接编辑章标题、篇章、范围、章目标、拍列表；「只重排剩下的拍」不会碰已经演过的部分
- **间章**：编辑标题 / 场合 / 日常画面列表；「换一段间章」「手动推进一个画面」「现在回主线」
- **支线/插曲**：逐条查看、标记完成、删除
- **设定**：自动化开关与节奏（含四道节奏闸门）、注入开关与深度、生成用上下文、世界书档位、外观

### 常用按钮

- **设计下一章** —— 让神谕按当前处境写一章（含拍列表）
- **重新生成本章** —— 整章推倒重写（正文模型报「这一拍站不住」时最有用）
- **只重排剩下的拍** —— 保留已演过的拍，只重写第 N 拍之后
- **开一段间章 / 现在回主线** —— 手动接管两种幕的切换（随时可以，不必等拍演完）
- **手动推进一拍** —— 模型忘了写回报时的纠偏
- **本章收尾** —— 直接标记整章演完（然后自动换章）
- **暂停自动导演** —— 停止一切自动调用（注入与手动按钮照常工作）

## 九、规则放在哪、怎么改

规则全在自带世界书「故事导演」里（8 条），面板「设定」页可以切档位：

## 十、常见问题

**Q：装了但什么都不发生？**
依次自查：MVU 有没有加载（面板「导演状态」里会写）→ 世界书「故事导演」有没有挂上 → 故事神谕扩展有没有启用 →
这个聊天有没有聊过至少一句（没有 MVU 变量时插件无法初始化命名空间）。

**Q：正文模型不写回报命令，拍一直卡在第一拍？**
模型没写时，下一轮引导还是同一拍（这是设计上的保守行为）。可以用面板的**手动推进一拍**纠偏；
也可以把注入深度调小（离最新一条更近），或在「设定」页检查变量契约注入有没有被关掉。

**Q：它自己在聊了几轮之后突然开了一章？**
默认 `autoDirector` + `autoChapter` 开着：没有拍列表、且这个聊天已经聊满 3 轮时，插件会请神谕开第一章。
不想要就关掉「自动换章」或「自动导演总闸」。

**Q：费 token 吗？**
每次生成（开章 / 支线 / 插曲 / 重排）都是一次**真实的模型调用**，上下文里会带世界书 + 近期对话 + 当前变量。
节奏默认比较保守（每 8 轮一条支线、每 6 轮一条插曲）；嫌贵就把这两个调大，或关掉自动导演。

**Q：会污染我的聊天记录吗？**
正文模型偶尔会把注入块的标签抄进回复里，插件会在回复落地后**确定性剥离**那个标签（只动它自己那一个）。
变量命令由插件自己接管落盘，不会写进正文。

## 十一、开发备注

- `model.js` 是纯逻辑（无 DOM、无酒馆 API），可以直接 `import` 起来写测试
- `index.js` 是全部副作用：MVU 接入、命令拦截、注入、神谕联动、自动导演心跳、面板
- 命令拦截是**承重设计**：角色卡普遍挂 `mvu_zod`，卡自己的 schema 会把未知根键 strip 掉，
  只改 `故事导演.*` 的命令会被静默丢弃。所以插件在 `mag_command_parsed` 里先把属于自己命名空间的命令
  套用到**活变量**上再摘除（见 `model.js` 顶部说明）

> 这套 MVU 接入与命令自管的写法沿用自**作者自己既有的另一套插件**（各写各的命名空间、互不干扰），
> 世界观与剧情规则则完全独立 —— 本插件不预设任何题材。
