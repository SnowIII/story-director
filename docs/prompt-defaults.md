## 字段写法 · 篇章 · 章内容

标记：`[sd_field_epic_chapters]`；返回字段：章内容。

```text
用途：约束「篇章 · 章内容」字段内部的生成写法。
输出时填写实际剧情内容，不复述本条规则。

写法要求：
每条对应一章。默认每条以〔舞台〕开头，再写「起：进入缘由 ｜ 承：诉求与代价 ｜ 转：关键变化 ｜ 合：局部结果」。
每章自己有起承转合，整部再形成一套更大的弧线；每章有自己要办的事，默认使用不同舞台，以暗线相连。
先排各章的舞台、要办的事与贯通的矛盾。不要把「起、承、转、合」直接当作四章标题，也不要把一件事拆成几天。
每章有可落定的局部结果，末章有归宿；大高潮之前积攒，之后留余波。不写分镜、台词或表情清单。
这里的内部小标题、叙事结构和舞台安排均可修改；一条一章的编号及本次章数仍按程序要求。
```

## 字段写法 · 主线 · 拍

标记：`[sd_field_chapter_beats]`；返回字段：拍。

```text
用途：约束「主线 · 拍」字段内部的生成写法。
输出时填写实际剧情内容，不复述本条规则。

写法要求：
每拍默认写「谁做了什么 → 于是局面变成什么样」，主语是 NPC、第三方或环境。
一拍只写一个来回：别人的动作及其当场造成的局面变化。收在把局面递到 {{user}} 面前，但不预设他如何回应。
拍与拍有因果，变化能看见；可交替使用对话、动作与沉默，不要每拍同一个形状。
默认章内依次呈现矛盾、压力、关键变化与局部收束，小高潮后留余波；承接篇章当前章的定位，不提前消耗后章的大高潮。
伏笔顺手长在当前场景里，具体到可以复述；不为凑伏笔新造设定，不埋完就解释。
好例子：「一名客商住进后巷客栈，第二天清早她的侍女向门口的守卫打听一封旧信。」
内部写法与小标题可以修改；拍数、局部重排范围和一行一条编号由程序决定。
```

## 程序提供的返回结构

示例以空白档案和默认数量渲染；实际数量、章节定位与进度在本次请求中提供。顶层字段名和编号保留，字段内部写法按上面的对应规则执行。

### 篇章

```text
按下面格式输出，标签原样照写，且**只输出一个区块**：

<StoryEpic>
标题: 〔篇章标题内容〕
篇章: 〔篇章概述内容〕
章内容: 共 4 条编号条目，每条对应一章，从 1 连续编号
1. 〔第一章内容〕
2. 〔第二章内容；按实际数量继续或删减编号项〕
大高潮: 〔高潮内容〕
伏笔: 〔伏笔内容；多项用分号或换行分隔〕
既成事实: 〔已确认事实内容〕
</StoryEpic>

然后在区块**外面**单独写一行结论（插件会把它念给用户听）：
检查: 〔检查结论内容；保持原计划时填写“照旧”〕
```
