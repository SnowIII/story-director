**Coop／羁绊：使用说明**

从故事导演面板的「支线/插曲」后面打开「Coop」页签。它仍使用故事导演的扩展安装和故事神谕模型连接。

**先选择角色。** 新聊天的名单为空。可以选择当前角色卡／群聊成员，也可以手动添加卡内 NPC 的姓名，补充设定可留空。每名角色有三种模式：

| 模式 | 行为 |
|---|---|
| 不管理 | 不维护好感、不生成个人 Coop 事件 |
| 仅维护好感 | 正常计分，不新建升阶事件 |
| 好感＋Coop | 计分、达到门槛后锁定、生成并演绎四阶事件 |

下拉框只读取酒馆当前打开的角色卡或群聊成员。已加入的角色会显示“已管理”，不能重复添加。D&D 等整合卡中的 NPC 不会自动从正文或世界书提取，请手动选择具体人物；已有设定由神谕在设计事件时从可用资料中提取。角色出场、被提及、成为反派或加入群聊，都不会自动加入名单。移出名单会暂停处理，原有好感、Rank、事件及锁继续保留；重新启用恢复原进度。

**补充设定（可选）。** 不必手动抄写人物档案。生成事件时，故事神谕会依据目标人物、所在角色卡／整合卡或群聊成员背景、相关世界书、近期真实对话，以及全部历阶摘要提取已有设定。补充栏仅保存你的额外说明，可以完全留空；旧内容保留，新加入的酒馆角色卡也不再整卡复制进补充栏。已有剧情与未来计划分开处理，补充内容不能静默改写已确认历史。

**全名与别名。** NPC 可用全名作为名称，在「别名／简称」填写同一人物的其他称呼，例如名称“英妮缇雅·维赛塔”，别名“英妮缇雅，维赛塔”。用逗号或换行分隔，最多12个；已有角色可在「编辑角色说明」中补充。所有称呼共用固定角色 ID、好感、Rank、事件与历阶摘要，不会因改名另起一条线。

不会自动拆分全名或猜测昵称。别名与其他角色的主名／别名重复时会提示冲突，请改用明确称呼；也避免用“她”“老师”等泛称。识别会统一中间点写法和英文大小写，并避免把“艾琳娜”当成另一名已管理的“艾琳”。实际称呼仍无法确认时，应先澄清，再维护好感。

**好感与 Rank。** 默认好感为 0～100，Rank 为已完成的阶级 0～4。四阶门槛固定为 30、60、90、100，不能自行修改。模型依据真实互动提交建议，插件验证原文依据后结算；普通聊天可以是 0，不会每句话都加分。

**同步到 MVU。** Coop 校验并保存计分后，自动将结果同步到最新消息楼层和聊天级 MVU 变量；状态栏可读取 `stat_data.故事导演.Coop.角色[角色ID].好感度`。角色 ID 固定，改名或使用别名不会另建一份；角色行显示可以复制的准确路径。每个角色同时提供 `名称`、`Rank`、`好感锁定`、`路线`、`管理模式`。

MVU 是已确认结果的读取入口，计分、门槛锁和事件归档仍由 Coop 负责。变量模型继续提交 Coop 回报，不直接改同步字段；MVU 更新时也会用已确认值校正这些字段。保存失败时保留旧值，来源失效、切换回复或重新加载后按有效日志同步。同步不覆盖角色卡其他变量、导演主线状态或 Coop 回报；MVU 未就绪时保留 Coop 进度，接口就绪后补同步。设置页显示接口可用性及同步错误。

达到下一阶门槛立即封顶并锁定，待触发阶段也锁。锁定期间正负变化均为 0，不保留溢出或待补发积分。比如 Rank 1、58 分收到 +5，只到 60；完成 Rank 2 事件并保存摘要后才解锁，保持 60 分，后续新互动再继续变化。

暂停、取消生成、关闭面板、改管理模式和刷新都不能解除既有锁。仅维护好感模式不会创建新门槛，但无法绕过此前已建立的锁。锁定只冻结分数，角色仍会对真实争执、承诺或背叛作出叙事反应。

**开始事件。** 就绪后在角色行点击「开始下一阶事件」。神谕读取角色设定、相关世界书、近期对话、全部已完成 Rank 摘要和未回收伏笔，设计当前一阶。具体情节动态生成，固定的是四阶人物弧光与当前事件结构：30 分建立联系，60 分揭开心结，90 分并肩破局并确认关系，100 分觉醒收束。

默认三轮：反常切入、困境与提问、根据用户回应收束。设置中可以选两轮，把切入与困境合并。问题没有得到真实回应时继续等待，不会因为回复数量足够就自动结算。群聊同一用户消息下的多条回复不算多次用户互动。

Rank 3 需要在面板确认「挚友／伙伴」或「恋人」。确认后继续聊天演绎结果，改变心意可以在收束前改选。系统不会用某个关键词猜测用户已经同意恋爱。

事件进行中会暂停故事导演主线、间章和普通支线的推进及节奏计数；暂停事件后释放场景，锁仍保留。默认手动开始，设置可以开启自动开始；自动化仍只处理已选角色，并要求角色可参与、场景空闲及全局自动生成允许。

**摘要与连续性。** 每阶完成时保存简短摘要、实际用户选择、局部结果、人物变化、未解决事项及已回收伏笔。设计 Rank 3 时带入 Rank 1～2，设计 Rank 4 时带入 Rank 1～3，不只读最近一阶。模型无法解释的历史冲突不采用。

「历阶摘要」中可以查看并修正有依据的摘要。修正会暂停依赖旧摘要的当前事件；使用「重设未演部分」后再继续，不修改已经发生的动作。共享 NPC 或信物状态会进行一致性核对，世界事实和角色可知范围分别记录。

若正文已经收束但回报缺失，可在「当前事件」点击「核对并补齐归档」。这只请求核对已有正文，不重演事件；证据不足时保持未完成。仅缺摘要措辞、但事实字段充分时，可直接按已确认字段整理摘要。

**保存与回退。** Coop 主档保存在宿主聊天元数据，独立于故事导演最近 24 个聊天切片。操作关联稳定消息 ID 和有效回复版本；重生成、切换回复、编辑或删除来源会重建有效进度，并同步撤销不再成立的 Rank、锁解除、路线和摘要。

图片锚点、AI 回复中的数字图片占位块（如 `<IMG>4</IMG>`）、导演自检清理和展示空行不会撤销已经发生的有效互动。图片占位兼容只移除已知格式，用户改变图片选择仍属于输入变化。原文校验采用与来源版本相同的正文提取规则；分析区提及的变量标签不能吞掉实际正文，真正的变量块也不能作为人物行动依据。修改较早互动后，后续独立且有效的加分会按顺序重新计算；完成 Rank 后取得的分数仍依赖该阶履历。

在「历阶摘要／档案」查看「最近互动处理」，可以区分已入账、正常 0 分、门槛锁定、未收到回报、原文依据不完整、来源改动和等待保存。旧版来源只在能重建其原始指纹时兼容；真实内容变化不会自动补分。旧档完成阶级后的依赖若不能核对，会继续显示待核对。

保存失败时显示待保存，不显示已成功升阶；恢复连接后重试保存。设置中可导出 JSON 并恢复同聊天档案。恢复校验消息来源，不会把另一聊天的经历当成当前事实。多窗口采用一个 Coop 写入方，其他窗口只读并跟随；接管前重新加载聊天。

**当前兼容边界。** MVU 使用 Coop 独立命名空间保存已确认数值，不强制绑定或覆盖角色卡已有的任意好感字段。需要状态栏改读上述路径；直接读取角色卡原字段不会自动关联。正文自行输出与额外变量模型两种回报路径均有自动化验证；严格卡片 schema 仍需允许 Coop 回报命名空间，具体卡片可能需要适配。

浏览器需提供 Web Locks 才开放写入；跨设备同时修改同一聊天目前按单活跃会话使用。叙事质量取决于模型，程序能限制阶段、结算及数据一致性，但无法绝对阻止正文抢跑；发现抢跑时不会据此代替用户结算。

**开发验证。** 在仓库根目录运行 npm test。测试不需要模型密钥。SillyTavern 1.19 的隔离宿主验收使用固定模型回应桩，验证实际菜单、注入、HTTP 存档、刷新和回退；这不等同于真实付费模型的叙事质量测试。

**档案升级。** 尚未产生计分或事件记录的旧版十阶档案会自动换成固定四阶门槛，保留名单及角色说明。已有十阶进度的档案会保留并停止写入，不静默重算或删除历史；需先导出旧档进行迁移。

## 每轮变量更新（0.39.7）

插件每轮把已管理角色的当前好感、Rank、锁定状态、计分规则与本轮 nonce 注入到故事导演共用的变量契约。好感不要求主线落拍，也不要求正在演出 Coop 事件。

随 AI 输出时，模型在正文之后现有的 `<UpdateVariable><JSONPatch>` 数组中添加 `/故事导演/Coop/回报`，其 value 是本轮完整报告；使用旧 MVU 命令格式的卡片可在同一个变量块内用 `_.set('故事导演.Coop.回报', 完整报告)`。两种格式只选一种。额外变量模型模式同样在它的变量更新块中提交报告，正文模型不单独回报。

回报包含固定角色 ID、变化量 delta、原因及双方消息原文依据，并必须携带本轮 nonce。最终好感仍由程序确认：没有依据、过期请求、重复互动和门槛锁不会被绕过。确认后的分数同步到 `故事导演.Coop.角色[角色ID].好感度`。

旧版 CoopReport 及已入账记录继续兼容读取。本次格式更新不会直接补写旧聊天分数。
