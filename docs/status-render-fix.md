# 状态栏偶发显示 HTML 代码的排查

涉及版本：故事导演 0.39.1 及更早的消息清理路径。修复版本：0.39.2。

## 触发链路

角色卡将 `<StatusPlaceHolderImpl/>` 经显示正则替换为带有代码围栏的 HTML。酒馆助手监听消息显示事件，再将该代码块挂载为 iframe 状态栏。

故事导演在清理回复中的自检、导演状态回声或 Coop 回报后，会调用 SillyTavern 的 `updateMessageBlock`。在本机的 SillyTavern 1.19.0 中，该函数重建 `.mes_text`，但不发出消息显示更新事件。因此旧 iframe 被替换掉后，酒馆助手可能没有机会重新挂载，界面留下状态栏的 HTML 代码。

这条路径只有在发生上述清理时触发，能够解释偶发性；它并不修改角色卡的正则配置。单凭本次排查不能排除其他扩展、未闭合的代码围栏或正则顺序造成的类似表现。

## 修复

- 清理后的消息统一通过刷新队列重建 HTML，再发出 `MESSAGE_UPDATED`，让酒馆助手和显示扩展恢复状态栏。
- 同一轮对同一消息的多次清理合并为一次刷新，异步显示通知顺序执行。
- 聊天已切换或消息对象已替换时，丢弃旧刷新任务。
- 保留角色卡状态栏占位符，不更改正则，不发出新的 `MESSAGE_RECEIVED` 或 `CHARACTER_MESSAGE_RENDERED` 来模拟一条新回复。

新增 7 项刷新与宿主适配测试，与其余测试合计 83 项通过。隔离宿主验证使用本机安装的 SillyTavern 1.19.0、酒馆助手 4.11.3 和角色卡中的实际状态栏正则，不调用模型。

实际宿主对照结果：初次渲染 iframe 数量为 1；只调用旧 `updateMessageBlock` 后变为 0，并留下 HTML 代码块；修复刷新后恢复为 1。再经过导演真实的自检和状态回声清理，等待原有延迟回调完成后 iframe 仍为 1。全过程核对正则配置序列化结果完全一致，占位符仍保留在原始消息中。
