# 按界面字段配置生成写法

当前提供 **22 个输出字段的写法**，以及一个可选的 `<preThink>` 返回前置内容条目。字段条目名以「字段写法 · 页面 · 字段」开头，末尾统一标注「（关闭使用默认设置）」，与界面框一一对应，内容直接展示用途和默认写法，不使用整段默认提示词宏。

页面输入框保存的是当前剧情结果。要改变 AI 以后生成的写法，请编辑框下方灰字指出的世界书条目；修改结果框本身不会改变生成规则。支线／插曲页及尚未创建篇章时，也提供字段条目目录。

## 怎么修改

1. 打开世界书「故事导演」，搜索框下方提示的字段名称。
2. 修改该条「写法要求」中的内容，保留名称中的 `[sd_field_…]` 方括号标记。
3. **开启该条目**并保存世界书。下一次设计、重新生成或重排未演部分时读取新要求。

22 个字段条目默认关闭；关闭时直接使用内置默认写法。开启后非恒定、无关键词，由插件按对应任务读取。不要为了生效改成常驻，否则可能被普通正文重复读取。关闭、清空或缺失一条时，只回退该字段的内置默认写法，不会使该字段消失，也不会阻止事件触发。

篇章检查在原计划仍成立时会照旧返回，不会仅因写法调整而改写旧计划；需要采用新写法时，主动重新生成或重排未演部分。

例如，把「字段写法 · 篇章 · 章内容」的要求改为：

~~~text
每章按「行动｜收获｜遗留问题」组织。
允许各章连续发生在同一地点，围绕共同实践和人物分工推进。
每条仍对应一章，按程序指定数量连续编号。
~~~

只会替换「章内容」的写法，标题、概述、大高潮等仍按各自条目执行；不会再额外附加另一套起承转合小标题或不同舞台要求。想改每拍内部的结构，则编辑「字段写法 · 主线 · 拍」，例如「现场、别人采取的行动、递到用户面前的局面」。

字段内可使用自定义小标题与多行内容；避免另起一行复用本任务的顶层字段名（如「章内容:」「章目标:」），以免被识别为下一个字段。

## 结果标签前的可选返回内容

世界书条目：**返回前置内容 · preThink（默认不输出）**，标记为 `[sd_return_prethink]`。默认内容为空，条目关闭，因此默认不会返回 `<preThink>`，也不会返回空标签。

在该条目填写希望返回的补充内容或写法要求，并开启条目。例如：

~~~text
先用两句话概括本次故事的主题与角色冲突，再列出一个后续可关注的悬念。
~~~

无需手写外层标签。神谕会在同一次回复中先返回：

~~~xml
<preThink>
按上述要求生成的补充内容。
</preThink>
<StoryEpic>
标题: …
篇章: …
章内容: …
…
</StoryEpic>
~~~

主线、间章、支线和插曲采用相同前置区块，后面仍是各自的 `<StoryChapters>`、`<StoryInterludeChapter>`、`<StoryThreads>`、`<StoryInterlude>`。关闭、清空或删除该条目后恢复原有返回格式；前置区块不写入页面剧情字段、Coop 档案或 MVU。Coop 的 JSON 事件设计不受此条目影响。

填写的是补充内容的生成要求；若需要固定文字，可写「原样输出：……」。前置内容与结果共用一次请求的输出额度，篇章检查结论仍在结果区块之后。

## 程序固定的内容

- 任务类型：新篇章、章末检查、校准、下一章或重排；角色卡、近期对话、当前章表与真实历史继续按本次请求提供。
- XML 标签、顶层字段名、编号列表、实际章数／拍数、局部重排范围与已经演过的部分。修改字段写法不改变进度。
- 玩家自主权、设定一致性、其他任务通则、正文演出引导和落拍审查。
- Coop 的设计蓝图、形式素材库、好感计分建议、成长与摘要规则、归档证据和事件队列。
- MVU 的变量路径、数值范围、门槛锁定与回报格式；世界书保留必需的 3 个机制条目。

字段条目只能改变该字段内部的写法。必要输出格式由程序最后提供；字段条目里自行写其他 XML 外壳或要求改成其他返回格式，不会改变插件读取协议。

## 动态参数

通常不需要写参数，程序会附上真实数量。需要在自定义写法中引用时，可使用以下值：

| 参数 | 用途 |
|---|---|
| {{sd.beatTarget}} | 整章拍数上限 |
| {{sd.beatBudget}} | 本次拍数预算，局部重排时为剩余预算 |
| {{sd.keep}}、{{sd.remaining}} | 保留拍数、剩余拍数 |
| {{sd.interludeBeats}} | 间章画面数 |
| {{sd.chaptersPerEpic}} | 每部篇章的章数 |
| {{sd.intensity}}、{{sd.tone}} | 当前节奏和基调 |
| {{sd.epicMode}} | establish／audit／evolve，仅用于篇章 |

只在有意义的任务里引用对应参数。{{user}} 等酒馆宏原样保留；文本不会当作代码执行。

## 旧版条目与升级

旧版 18 个整段提示词条目、5 个 Coop 模板条目直接删除，不保留存档，也不再参与请求。不要把旧整段提示词粘进新字段条目，它会混入其他字段的要求。

世界书自动更新开启时，0.43.0 未修改的默认字段在升级后转为关闭；已有自定义内容及其开关保留。本版之后明确开启的字段及前置内容配置在后续更新中继续保留。若关闭了世界书自动更新，可到「设定」手动重装；手动重装会恢复本版默认值：22 个字段关闭，preThink 留空且关闭，3 个 MVU 机制条目开启。

既有剧情结果、Coop 角色档案、Rank 历史摘要和已确认设定不会被此次条目整理改写。已生成的计划仍按原内容演出，修改写法在后续设计时生效。没有增加任何模型调用。

所有默认写法及必要返回结构见 [默认写法参考](prompt-defaults.md)。自动验证使用固定数据与内存宿主，覆盖字段独立生效、实时参数、历史保护、升级删除、单次请求以及页面条目指引；没有调用真实模型。
