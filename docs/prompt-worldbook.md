# 按界面字段配置生成写法

当前提供 **23 个输出字段的写法**，以及五类任务独立的 `<preThink>` 返回前置内容、Coop 4／7／10 阶蓝图配置。字段条目名以「字段写法 · 页面 · 字段」开头，末尾统一标注「（关闭使用默认设置）」，与界面框一一对应，内容直接展示用途和默认写法，不使用整段默认提示词宏。

页面输入框保存的是当前剧情结果。要改变 AI 以后生成的写法，请编辑框下方灰字指出的世界书条目；修改结果框本身不会改变生成规则。支线／插曲页及尚未创建篇章时，也提供字段条目目录。

## 怎么修改

1. 打开世界书「故事导演」，搜索框下方提示的字段名称。
2. 修改该条「写法要求」中的内容，保留名称中的 `[sd_field_…]` 方括号标记。
3. **开启该条目**并保存世界书。下一次设计、重新生成或重排未演部分时读取新要求。

23 个字段条目默认关闭；关闭时直接使用内置默认写法。开启后非恒定、无关键词，由插件按对应任务读取。不要为了生效改成常驻，否则可能被普通正文重复读取。关闭、清空或缺失一条时，只回退该字段的内置默认写法，不会使该字段消失，也不会阻止事件触发。

篇章检查在原计划仍成立时会照旧返回，不会仅因写法调整而改写旧计划；需要采用新写法时，主动重新生成或重排未演部分。

例如，把「字段写法 · 篇章 · 章内容」的要求改为：

~~~text
每章按「行动｜收获｜遗留问题」组织。
允许各章连续发生在同一地点，围绕共同实践和人物分工推进。
每条仍对应一章，按程序指定数量连续编号。
~~~

只会替换「章内容」的写法，标题、概述、大高潮等仍按各自条目执行；不会再额外附加另一套起承转合小标题或不同舞台要求。想改每拍内部的结构，则编辑「字段写法 · 主线 · 拍」，例如「现场、别人采取的行动、递到用户面前的局面」。

字段内可使用自定义小标题与多行内容；避免另起一行复用本任务的顶层字段名（如「章内容:」「章目标:」），以免被识别为下一个字段。

### 大纲遵循强化

主线生成在原有请求中同时返回「拍」与「剧情锚点」两组编号列表，条数相同、逐拍对应。锚点是该拍不可缺少的结果，例如「旧信交到守卫手中；来信者身份明确」，由插件保存，可在主线页查看和编辑。局部重排同时保留已演拍及锚点；返回缺失或错配的锚点时，不采用这份新章表。

「设置 → 注入 → 大纲遵循强化」默认不勾选。勾选后，每轮向正文引导注入当前拍锚点，要求模型结合当前处境、人物动机与知情范围，安排必要的铺垫和触发条件，通过连续的行动、反应与局面变化实现锚点。原路径受阻时主动寻找合理替代路径，缺少铺垫就把铺垫写出来；只有目标与既成事实或玩家明确选择直接冲突、合理路径确实走不通时，才使用原有审查。

当前拍可跨轮展开，尊重玩家回应。落拍沿用原有拍进度规则，锚点不新增逐项核销条件；仅修改锚点也不重置原有落拍状态。已落拍等待换拍时只写余波，不为补齐锚点重演。旧章表没有独立锚点时沿用对应拍内容，不额外调用模型。

锚点的表达方式可编辑并开启世界书 `[sd_field_chapter_anchors]`；字段名、编号及与拍的对应关系由固定协议维护。世界书条目开关控制生成写法，设置页勾选项控制正文约束，两者独立。

## 结果标签前的可选返回内容

五类任务各有一个独立条目，默认留空且关闭，因此默认不返回 `<preThink>`，也不会返回空标签。

| 世界书条目 | 标记 | 后接的结果标签 |
|---|---|---|
| 返回前置内容 · 篇章 · preThink（默认不输出） | `[sd_return_prethink_epic]` | `StoryEpic` |
| 返回前置内容 · 主线 · preThink（默认不输出） | `[sd_return_prethink_chapter]` | `StoryChapters` |
| 返回前置内容 · 间章 · preThink（默认不输出） | `[sd_return_prethink_interlude_chapter]` | `StoryInterludeChapter` |
| 返回前置内容 · 支线 · preThink（默认不输出） | `[sd_return_prethink_thread]` | `StoryThreads` |
| 返回前置内容 · 插曲 · preThink（默认不输出） | `[sd_return_prethink_interlude]` | `StoryInterlude` |

编辑并开启要使用的任务条目即可，无需手写外层标签。例如在「返回前置内容 · 篇章 · preThink」填写：

~~~text
先用两句话概括本次故事的主题与角色冲突，再列出一个后续可关注的悬念。
~~~

同一次回复会先返回 `<preThink>按要求生成的补充内容</preThink>`，再接 `<StoryEpic>…</StoryEpic>`。修改主线前置内容只影响主线；间章、支线和插曲同理，关闭或留空不会借用其他任务的配置。前置内容不写入页面剧情字段、Coop 档案或 MVU，Coop 的 JSON 设计不使用这五个条目。

上一版共用 `[sd_return_prethink]` 在自动升级时将内容与开关复制到五个新条目，随后移除。已存在的任务独立条目优先，即使它明确留空或关闭，也不会被旧共用内容覆盖。运行时不再读取旧共用条目。

前置内容与结果共用原有请求及输出额度，篇章检查结论仍写在结果区块之后。

## Coop 阶级蓝图自定义

| 世界书条目 | 标记 | 包含阶段 |
|---|---|---|
| Coop · 4 阶蓝图 | `[coop_rank_4]` | Rank 1～4 |
| Coop · 7 阶蓝图 | `[coop_rank_7]` | Rank 1～7 |
| Coop · 10 阶蓝图 | `[coop_rank_10]` | Rank 1～10 |

三套蓝图均展示完整默认文本，默认关闭，名称末尾标注「（关闭使用默认设置）」。修改并开启所需方案后生效。角色依旧使用建档时已锁定的 4、7 或 10 阶方案，不会因为另一方案开启而切换。

保留 `## Rank 1`、`## Rank 2` 等阶段标题，修改对应段落的成长目标与事件写法。每次设计只发送当前目标 Rank 的段落；第一段标题之前的文字作为该方案的共同要求。若只写一段不带 Rank 标题的创作偏好，则用于该方案各阶。

关闭、清空、缺少当前 Rank、当前段落为空或同一 Rank 标题重复时，回退当前阶的内置蓝图。自定义内容与开关会保留到后续升级，未修改的默认全文随内置版本更新。

可用变量：`{{coop.rankCount}}`（方案阶数）、`{{coop.relationshipRank}}`（关系确认阶）、`{{coop.thresholds}}`（固定门槛）、`{{coop.targetRank}}`（本次目标阶）；`{{user}}` 等酒馆宏原样保留。

这里只开放叙事蓝图，通用设计规则与形式素材库仍固定。好感门槛、关系确认节点、当前事件互斥、真实用户回应、既有摘要、JSON 返回结构与本阶完成条件不可由蓝图改写。已生成事件继续使用已有计划，修改在后续设计或重设未演部分时生效。完整阶段说明见 [Coop 阶级蓝图](coop-rank-plans.md)。

## 程序固定的内容

- 任务类型：新篇章、章末检查、校准、下一章或重排；角色卡、近期对话、当前章表与真实历史继续按本次请求提供。
- XML 标签、顶层字段名、编号列表、实际章数／拍数、局部重排范围与已经演过的部分。修改字段写法不改变进度。
- 玩家自主权、设定一致性、其他任务通则、正文演出引导和落拍审查。
- Coop 的通用设计规则、形式素材库、好感计分建议、成长与摘要规则、归档证据和事件队列；阶段叙事蓝图按上面的独立条目配置。
- MVU 的变量路径、数值范围、门槛锁定与回报格式；世界书保留必需的 3 个机制条目。

字段条目只能改变该字段内部的写法。必要输出格式由程序最后提供；字段条目里自行写其他 XML 外壳或要求改成其他返回格式，不会改变插件读取协议。

## 动态参数

通常不需要写参数，程序会附上真实数量。需要在自定义写法中引用时，可使用以下值：

| 参数 | 用途 |
|---|---|
| {{sd.beatTarget}} | 整章拍数上限 |
| {{sd.beatBudget}} | 本次拍数预算，局部重排时为剩余预算 |
| {{sd.keep}}、{{sd.remaining}} | 保留拍数、剩余拍数 |
| {{sd.interludeBeats}} | 间章画面数 |
| {{sd.chaptersPerEpic}} | 每部篇章的章数 |
| {{sd.intensity}}、{{sd.tone}} | 当前节奏和基调 |
| {{sd.epicMode}} | establish／audit／evolve，仅用于篇章 |

只在有意义的任务里引用对应参数。{{user}} 等酒馆宏原样保留；文本不会当作代码执行。

## 旧版条目与升级

旧版 18 个整段提示词条目以及 Coop 通用设计／形式库条目继续删除，不保留存档。4／7／10 阶蓝图已按上述三条重新开放。不要把旧整段提示词粘进新字段条目，它会混入其他字段的要求。

世界书自动更新开启时，0.43.0 未修改的默认字段在升级后转为关闭；已有自定义内容及其开关保留。本版之后明确开启的字段及前置内容配置在后续更新中继续保留。若关闭了世界书自动更新，可到「设定」手动重装；手动重装会恢复本版默认值：23 个字段关闭，5 个 preThink 留空且关闭，3 套 Coop 蓝图关闭并恢复默认全文，3 个 MVU 机制条目开启。

既有剧情结果、Coop 角色档案、Rank 历史摘要和已确认设定不会被此次条目整理改写。已生成的计划仍按原内容演出，修改写法在后续设计时生效。没有增加任何模型调用。

所有默认写法及必要返回结构见 [默认写法参考](prompt-defaults.md)。自动验证使用固定数据与内存宿主，覆盖字段独立生效、实时参数、历史保护、升级删除、单次请求以及页面条目指引；没有调用真实模型。
