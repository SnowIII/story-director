# 提示词清单与世界书自定义

故事导演的提示词分给三个读者：**故事神谕**负责设计，**正文模型**负责按当前计划演出，**MVU 变量模型**负责更新数值和落拍字段。Coop 的事件回报由正文模型直接交给导演，不经过额外变量模型。

0.42.0 新增 18 个独立提示词条目，原有 5 个 Coop 设计条目继续使用。它们都在酒馆世界书 **「故事导演」** 中。每条独立判断开关：**开启且内容非空时使用世界书内容；关闭、缺失或留空时使用对应的内置默认值**。

## 怎么修改

1. 打开酒馆世界书「故事导演」，找到对应标签的条目。
2. 编辑内容，保留条目名中的方括号标签，开启条目并保存。
3. 下一次设计或正文生成会重新读取。关闭条目即可恢复内置规则。

这些条目保持默认的 **非恒定、无关键词** 触发方式，由插件按用途读取，不需要设置关键词或把它们设为常驻。设计规则只发给对应设计任务，不随每轮正文重复发送整本世界书。

共用规则条目中放的是对应默认规则全文。完整任务和动态正文引导的条目默认放 **`{{sd.default}}`**，它会展开为当次完整的内置提示词，包括运行时填充内容。不是固定抄录一份第一章的提示词，因此检查篇章、重排剩余拍等任务仍会得到各自正确的默认内容。

例如，想在内置章节规则上增加偏好，可以把 `[sd_prompt_chapter]` 改成：

```text
{{sd.default}}

本次额外创作偏好：优先使用共同实践、协商和具体成果推进人物关系。
```

若想**替换**完整设计提示词，删掉 `{{sd.default}}`，直接写自己的内容：

```text
你是当前章节的剧情设计师。依据本次提供的真实历史和章表，
用人物的实际目的组织因果；优先写合作、发现与承担责任，
让不同立场都有合理行动，不反复安排同一种救援结构。
```

程序会补上当次任务类型、数量、已演内容保护和返回区块格式。不会再无条件叠加被替换的默认创作规则。完整任务条目不引用内置提示词时，七组共用设计规则也不会强行追加；要只微调某一层，直接编辑对应共用规则条目即可。

设计类条目还可以使用 `{{sd.beatTarget}}`、`{{sd.interludeBeats}}`、`{{sd.chaptersPerEpic}}`、`{{sd.intensity}}`、`{{sd.tone}}`。局部重排可用 `{{sd.keep}}`、`{{sd.remaining}}`；篇章任务可用 `{{sd.epicMode}}`。后面三个只在对应任务有意义。`{{user}}`、`{{char}}` 等酒馆宏保持原样；不认识的宏不会执行成代码。

原有 `[coop_design]` 和阶级流程继续支持 `{{coop.rankCount}}`、`{{coop.relationshipRank}}`、`{{coop.thresholds}}`，含义和开关行为保持原样。开启新的成长条目时，也会替换未编辑的旧 Coop 通用模板中相同的默认成长段落。

## 程序仍负责什么

以下内容属于运行数据或读写协议，不能靠改提示词改写进度：

- `buildUserPrompt`、`collectContextBlocks` 组装的角色卡、激活世界书、近期对话、当前章表、已演拍和真实归档。
- `renderMainSection`、`renderThreadsSection`、`renderInterludeSection`、`renderInterludeChapterSection` 中当前实际要演的内容、顺序与进度。
- `<StoryEpic>`、`<StoryChapters>`、`<StoryInterludeChapter>`、`<StoryThreads>`、`<StoryInterlude>` 的必要返回字段。
- MVU 的命名空间、路径、0～100 上限、门槛锁定、当前角色名单和当前实际值；Coop 的证据、事件 ID、阶段、路线确认、JSON 格式及现场收束检查。
- 自检标签、落拍字段及由谁回填的分工。审查执行建议可编辑，标签和状态机处理方式继续由代码决定。

Coop 当前阶段、真实用户选择、场景队列及直接回报契约来自 `coop/prompts.js`；它们与可编辑的成长和计分建议共同组成每轮提示。新功能不增加神谕或正文 API 调用，也不会为读取世界书请求额外模型。

## 更新与生效范围

自动升级会增加缺失的条目，保留用户自定义文本与开关；未编辑的默认文本随版本更新。原有 Coop 模板的保留行为不变。手动重装世界书会恢复默认内容。

设计类修改在下一次设计或「重设未演部分」时生效，已生成计划和历史归档不会被追溯改写。演出、计分和成长规则在下一次正文准备时读取；保存世界书设置也会刷新已有注入缓存。已有完整归档回报继续直接采用，不因自定义归档提示词多发一次核对请求。
